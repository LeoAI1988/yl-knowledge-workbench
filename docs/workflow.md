# 知识怎样进入、组织和被使用

Markdown 保存正文，YL Skills 处理知识，工作台提供阅读和使用界面。原文始终是可回看的依据。

## 用 YL 构建知识库

安装 [YL Skills](https://github.com/LeoAI1988/yl-skills) 后，在支持 Skills 的 Agent 中使用 `yl-knowledge`。已有库接入原结构，不新建平行正文；新库由 `yl-knowledge-build` 建立目录、个人配置与来源登记。

可以这样提出任务：

> 使用 yl-knowledge，接入我指定的笔记目录。保留原文件，区分本人原话和外部资料，完成归档、蒸馏、去重、表达资产、关系与检索更新，并报告未完成项。

这是 Agent 调用范例；插件没有把它变成自动执行按钮。首次接入需明确目录与归属，宿主需有相应权限。

## 入库不止是复制文件

1. **收进原件。** 登记本次范围，保留原录音、原稿；清洗稿另存。
2. **看清是谁说的。** 本人、他人引用、多人录音、AI 整理分开，不能因为文件在你的库里就都当成你的观点。
3. **核对版本。** 同一正文不重复堆放，修订保留版本与出处。
4. **阅读全文再提炼。** 找可复用观点、方法、案例，保留原话、语境和思路推进。不能只读摘要，也不为凑数把每段做成卡。
5. **语义去重。** 同一意思补充旧卡来源与新表达；真实变化保留延展、应用或冲突关系。
6. **整理表达与结构。** 比喻、口头说法、开头、收尾回指原文；知识可跨领域关联，正文不重复复制。
7. **更新检索并检查。** 新正文即使没提炼出原子也要能搜到。检查覆盖、引用、关系、索引及未完成项。

语义判断由执行 Skills 的 Agent 完成，脚本负责登记与可计算校验。插件不会凭一个类型标签证明“已蒸馏”。

## 普通 Obsidian 库怎么用

直接读取 Markdown 属性与真实双向链接。`type` 确定卡片用途，`domains` 确定领域；见 [演示库](../examples/demo-vault)。专用 YL 适配器还读取统一对象、关系、表达、论述与作品登记；需要对应数据结构，不是任意文件夹都兼容。

## 问答怎么调用

问题与选中的知识 → 本机检索 → 取相关原文和上下文 → 交给已登录 Codex 的模型 → 展示回答与来源。

普通库按文本匹配取最多 8 份材料，每份上限 10,000 字符，不等同于全库完整阅读；大型长文应配合 YL 的段落级检索。已有 YL 库按自己的全文/语义配置运行。模型接收本次证据和最近几条对话，仍可能误解或漏检，引用按钮用于回读核对。当前检查可拒绝不存在的引用编号，不能保证每一句已经语义验证。

## 从灵感到初稿

保存原话并注明归属 → 拆解原本受众 → 比较 2—3 个扩大受众方向 → 选择 → 用相关原文组织初稿。

每个方向给出开头、至少三个不同亮点、推进结构、结尾、留言/私信/产品承接和暂估播放档位。没有流量承诺；无历史可比样本时依据不足，没有实时热度检索。AI 草稿独立保存，不会自动成为本人原话、正式知识或已发布作品。

生成后仍需审稿。正式入库与发布分别交给对应流程，不由插件静默执行。
