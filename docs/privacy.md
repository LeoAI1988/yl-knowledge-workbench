# 资料、模型与存储

代码可以公开，个人库不需要公开。仓库与安装包不含作者原文、头像、知识对象、经营指标、聊天或凭据。`examples/` 与截图只有明确标记的虚构演示资料。

| 数据 | 位置 |
|---|---|
| 原文、知识卡、表达、作品 | 当前 Obsidian 库 |
| 新灵感 | 库内 `03_选题库/灵感` |
| AI 初稿 | 库内 `02_我的作品全集/工作台草稿` |
| 普通库配置、分析、对话、日志 | 用户目录 `.config/yl-workbench/<库标识>/` |
| 已有 YL 用户运行资料 | profile 的 workbench.runtime；未设时为 `.config/yl-toolbox/runtime/knowledge-workbench` |
| 插件界面设置 | 插件目录内 `data.json` |

备份时保留库和对应运行目录。运行目录不是加密保险箱；同设备账户可读取，自行云同步时需考虑范围。

## 什么时候联网

浏览、原文阅读、卡片检索、保存灵感由本机完成。问答、选题和写初稿通过本机 Codex 向推理服务发送本次材料、问题或近期对话，受 Codex 账号与服务政策约束，并非离线 GPT。检查模型连接也会连接 Codex。项目不收集遥测，不内置开发者 API Key，不自动上传整个库。

HTTP 服务只监听 `127.0.0.1`，检查 Host、Origin 与客户端请求头。它没有公网账号隔离和认证，不要直接反向代理到互联网。

## 控制索引范围

普通适配器跳过隐藏目录、`node_modules`、`80_私人档案`、`90_系统资料`、符号链接和目录联接。`privacy: P2`、`privacy: P3`、`privacy: private` 或 `index: false` 会排除文件。

配置的 `workbench.exclude_folders` 可填额外文件夹名称，刷新后生效；下次打开会保留。它按目录名称排除，不是任意路径匹配。排除不会擦除已发送材料或旧对话。YL 适配器遵循其审核来源清单和访问规则。

集成禁用模型工具调用、文件读取和外部写入；素材中的指令按数据处理。限制权限不能保证回答永远正确。

## 开源与私人分身

用户使用自己的库，不需要作者原文件。分发到别人的设备的明文文件不能保证“可调用但不可阅读”。私人分身对外服务需要另建服务端权限、检索与审查；本版不包含这项服务。
